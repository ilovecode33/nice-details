# Component entry criteria

Scope: Applies to the shared @ilovecode33/ui library.

Every PR adding a component must satisfy all of the following:

- [ ] **Single responsibility** — its purpose is one sentence; no overlap with existing components.
- [ ] **Minimal API** — props extend native HTML attributes where possible; no boolean-flag
      explosion.
- [ ] **Complete types** — all types from `ui` and `ui-core` live in `@ilovecode33/ui-types`,
      grouped by domain (`semantics`, `deform`, `toggle`, `selection`, `disclosure`, `list`,
      `sheet`, `field`, `feedback`, `media`, `navigation`, `floating`, `appearance`, `foundation`,
      `primitives`), not by source package. Consumers import types from `@ilovecode33/ui-types`
      directly; `ui` and `ui-core` do not re-export them. `tsc --noEmit` passes.
- [ ] **Landing page showcase** — at least one real usage scenario in `apps/ui-landing` under
      **Component details**, not an isolated button array.
- [ ] **Accessible** — correct role, aria-label, focus ring, 44pt touch target.
- [ ] **Design tokens only** — every custom property, including derived recipes (`--icon-*`,
      `--glow-*`, `--seg-thumb-*`, `--btn-glow*`, `--bg-gradient`), is generated by
      `@ilovecode33/ui-tokens` (`generated/styles.css`). `ui/src/styles.css` only imports that
      generated CSS and adds base resets plus `[data-ui~=...]` rules; no hand-written token block.
- [ ] **Colocation & coverage** — every component lives in `src/components/<Component>.tsx` next to
      its `<Component>.module.css` and `<Component>.spec.tsx`, all named after the component. Hooks
      live in `src/hooks/<hook>.ts` with a `<hook>.spec.tsx`; components import them from there
      rather than defining them. Every component and hook has a spec; `ui-core` contracts are
      covered by `core.spec.ts`. Each `<Component>.spec.tsx` includes a
      `matches its structural snapshot` case that writes its own
      `src/components/__snapshots__/<Component>.spec.tsx.snap` via the shared
      `src/test-utils/snapshot.ts` helper; a new component needs that case in its own spec. The
      helper normalizes React-generated ids to `ID` and clears provider storage before each case, so
      snapshots only change when markup changes. Regenerate deliberately with `bunx rstest run -u`
      in `packages/ui` — never hand-edit a `.snap` file.
- [ ] **Stylesheet ownership** — class names are read directly from the imported CSS Module
      (`styles['ui-btn']`); no class-name mapper is used. A rule must not target a class defined in
      another module — import that module's own class map instead. Public styling hooks are stable
      `data-ui` slots (`data-ui="stack stack--md"`) styled by `[data-ui~='...']` rules in
      `src/styles.css`; consumers must not depend on hashed CSS Module class names, and `cn()` is
      removed.
- [ ] **Mobile-first CSS** — phone base rules; no horizontal scrolling at 375px.
- [ ] **Reduced motion** — animation is disabled when `prefers-reduced-motion: reduce` is set.
- [ ] **No new runtime dependency** — if one is needed, explain why first. The one exception is
      `lucide-react`: UI icons were previously raw Unicode characters (e.g. `☀`, `✕`, `⌃`) whose
      glyphs vary by platform font and cannot be sized or stroked consistently. Lucide gives every
      icon a uniform stroke and a `ReactNode` API that fits existing `icon` props; tree-shaking
      keeps only the imported icons. Icon sizes come from `--icon-sm/md/lg` tokens via
      `svg:global(.lucide)` (CSS Modules hashes plain `.lucide`).
- [ ] **No i18n dependency** — all text passed via props with English defaults.
